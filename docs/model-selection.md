# 模型选型与延迟实测

**默认：`sherpa-onnx-x-asr-160ms-...-2026-06-05`**

下面所有数字都是同一套测法得到的：`tools/probe_stream.py` 把真实录音按真实的
32ms 节拍喂给 sidecar（不是一次性灌完），再按墙钟记录文本更新的时刻。
「本机」指一台普通的 x86-64 桌面 CPU（Windows 11 x64，推理全在 CPU 上，没有独显参与）。

---

## 1. 跟手感：延迟到底卡在哪

结论先说：**卡在模型，不在 sainput**。延迟分三段：

| 段 | 实测 | 能不能再压 |
|---|---|---|
| 第一个字：说出口 → 屏幕上出现 | 语音起点之后 **770~860ms** | 只能换模型 |
| 之后每个字的刷新间隔 | p50 **320ms**，每次 1~4 个字 | 由模型 chunk 决定；实测最小间隔 160ms |
| 松手 → 最后一个字上屏 | **200~560ms**（含补底噪往返约 130ms） | 见 README 的「尾巴」一节 |

`throttle_ms` 实测（同一段真实语音、按真实 32ms 节拍喂帧）：

| throttle_ms | 文本更新次数 | 更新间隔 p50 | 每次新增字数 |
|---|---|---|---|
| 0 | 15 | 320ms | 1 2 2 3 1 1 2 4 0 4 2 1 1 1 |
| 40 | 15 | 320ms | 同上 |
| **80（默认）** | 15 | 288ms | 同上 |
| 160 | 14 | 320ms | 同上 |
| 320 | 10 | 320ms（每次跳 6 个字） | 3 2 4 1 6 6 1 1 1 |

**0 / 40 / 80 三档完全一样 → 80 已经等于不限流，再往下压没有收益**；反过来 320 会明显变顿。
首个字位置在 0~160 三档里都是 992ms，说明它跟节流无关。

## 2. 分块还能不能更小

翻完 sherpa-onnx 官方 `asr-models` 全部 **498 个 asset**：中文 / 中英流式模型只有
**160 / 480 / 960 / 1920ms** 四档，**没有比 160ms 更小的中文档**。

唯一 <160ms 的是多语种 **NVIDIA Nemotron-3.5 streaming 0.6B（80ms 分块）**，已下载实测：

| 指标 | Nemotron 80ms 0.6B |
|---|---|
| 中文可用性 | 能认对（`不要问你的国家能为你做什么, 而问你能为你的国家做什么`） |
| 首个字 | **555ms**（比 160ms 档快约 250~300ms） |
| 刷新间隔 p50 | **192ms** |
| CPU | 0.6B 参数，2 线程**比实时慢**（墙钟更新间隔 337ms > 音频间隔 192ms，越说越落后）；8 线程才勉强追平（204ms vs 192ms），CPU 基本吃满 |

**结论：想更快只能换引擎 / 换硬件；sainput 这一侧已经压到底了。**

## 3. 为什么换掉 2023 双语档（同一批真实语音横评）

同一批真实语音横评（`zh-14M/test_wavs` 是真实中文录音，`bilingual/test_wavs` 是中英混说）：

| 模型 | 真机中文重复标记 | 中英混说 | RTF |
|---|---|---|---|
| x-asr-480ms | **0** | `昨天是MONDAY TODAY IS礼拜二，THE DAY AFTER TOMORROW是。` | 0.10 |
| x-asr-160ms | 0 | `…TODAY IS 礼拜二 TODAY AFTER TOMORROW`（丢词） | 0.22 |
| x-asr-960ms | 0 | 同 480ms | 0.07 |
| streaming-zipformer-zh-int8-2025-06-30 | 0 | 英文全乱（`MANDYTEDIS里巴奥`） | 0.15 |
| bilingual-zh-en-2023-02-20（旧默认） | **4** ❌ | `LIBR THE DAY AFTER TOMORROW`（英文最好） | 0.08 |
| zh-14M-2023-02-23 | 0 | 英文差 | 0.07 |

旧默认档在真机中文上会**重复打转**：

```
重点重点呢想谈谈三个问题首先呢就是这一轮全球金融动动动荡荡荡的表现
```

x-asr-480ms 同一段音频输出：

```
重点呢想谈三个问题，首先呢就是这一轮全球金融动荡。
```

干净，而且 `MONDAY` / `THE DAY AFTER TOMORROW` / `ALWAYS` / `FREQUENTLY` 这些英文词它都认得出。

## 4. 备选档

| 档 | 适合 |
|---|---|
| x-asr-480ms | 比 160ms 更准（英文更完整），但每次刷 3–4 个字、手感更顿 |
| x-asr-960ms | 最省 CPU（RTF 0.068），手感最差 |
| streaming-zipformer-zh-int8-2025-06-30 | 纯中文，用词更准；**英文会听成乱码** |
| bilingual-zh-en-2023-02-20 | 英文识别最好；**中文长句会打转**，除非你几乎只讲英文 |
| zh-14M-2023-02-23 | 体积最小（约 24MB 权重），够用就好 |
| nemotron-3.5-asr-streaming-0.6b-80ms-int8-2026-06-11 | 80ms 分块、首个字最快（555ms）、中文可用；**代价是 CPU**：要多线程才追得上实时，模型约 627MB。想试就把 `model_dir` 指过去并 `threads = 8` |

换档只改 `sainput.conf` 一行：

```ini
model_dir = models/sherpa-onnx-x-asr-480ms-streaming-zipformer-transducer-zh-en-int8-2026-06-05
```

模型下载见 [`../models/README.md`](../models/README.md)。

## 5. 别再重复试的方向（已证无效）

- `beam = true`：更容易出错（「昨天」→「昨天天」），耗时无优势。
- 调 `blank_penalty`（0 / 0.5 / 1.5）：输出逐字相同 —— 这也是它被从配置项里去掉的原因。
- 把音频衰减到 -40dB：重复度基本不变 —— 重复不是电平问题。
- 把 `throttle_ms` 压到 0：文本更新次数与 80 完全一致。

## 6. 重复修复兜底（`tools/repair.py`）

换模型消掉了绝大部分打转，但模型永远可能偶发，所以渲染链最前面还有一道保守修复：

- 同一个字连续 ≥3 次 → 压成 1 个（`叠叠叠叠叠叠` → `叠`）；笑声字压到 2 个（`哈哈哈` → `哈哈`）
- 含中文的 3 字以上片段原样重复 → 保留一次（`为什么为什么` → `为什么`）
- 「不叠字」的字连着两遍 → 一个（`识别别` → `识别`）

**不许动**的正常内容：`看看` / `刚刚` / `妈妈` / `天天` / `慢慢` / `很多很多` / `一步一步` /
`可以可以` / `ALWAYS ALWAYS`（22 项自测：`python tools\repair.py`）。

## 7. 怎么自己复测

```powershell
python tools\probe_stream.py --wav <你的录音.wav>
python tools\bench_models.py
```

两个脚本都会直接打印上表里那几列（首个字、刷新间隔、RTF）。
录音用 `run.bat record out.wav --seconds 10`，然后对着麦克风正常说话。
